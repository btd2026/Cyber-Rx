Model your enterprise — not a compliance checklist

One living model of your enterprise, from Corporate down to every control.

Nerion assesses a global program along a single chain — Corporate → Region → Entity → Process → System → Risk → Control. You define the structure and the operating model (which controls corporate provides once and every unit inherits — the NIST General Support System / common-control model); Nerion discovers your systems, derives the risks each one carries, and continuously assesses all 106 NIST CSF controls from live telemetry — not a point-in-time audit. This setup walks that chain top to bottom. Everything is optional and editable later.
Built for the global enterprise
A compliance-automation tool collects point-in-time evidence for one framework at one entity. Nerion is built for a global enterprise: multi-region scope with 10+ entities per region, control inheritance (corporate common controls vs what each unit runs), continuous telemetry-driven scoring of all 106 NIST CSF controls, and materiality-first triage across 1000s of systems. You define the structure once; the rest is discovered, risk-mapped and scored continuously.

Organizational structure (regions & entities)
Your global footprint — the regions and the legal entities / branches under each. Nerion scopes the whole cockpit to any level you pick (Enterprise → Region → Entity): the group CISO sees the consolidated roll-up, each regional CISO sees their own posture, and privacy/regulatory obligations attach per region. Tick “own systems & docs” on a branch that connects its own tools and uploads its own policies (e.g. EMEA on Defender with a GDPR data-protection policy); leave it unticked and the branch inherits the region/enterprise — so a global policy is uploaded once, and you override only where a branch genuinely differs. Leave it empty and Nerion runs single-entity. Every region must contain at least one entity — a region’s score is the average of its entities and Enterprise is the average of its regions, so a region with no entities has nothing to measure and is not shown. If a region doesn’t apply to you, simply leave it out.

Security operating model (common vs system-specific controls)
Global firms don’t assess every control per region from scratch. Some are common controls provided once by corporate — a global IdP, the corporate SOC, enterprise governance — and inherited by every region; the rest are system-specific, run by each region. Nerion then inherits correctly: a region can’t score below the corporate baseline on an inherited control, and only its own controls vary. This is the NIST General Support System → Major Application model.

Systems — discover, don’t type
A global estate is thousands of systems — you don’t enumerate them by hand. Three ways to bring them in: connect a discovery source (enter its instance URL & API token — Nerion pulls the inventory read-only), upload a CSV / spreadsheet if you don’t run a CMDB, or paste a short list. Each system is placed in its region and asset class so controls score per system and roll up to the region. This is the discovery layer that fills the structure skeleton you defined above.

Continuous-monitoring cadence (how often controls re-check)
Every one of the 106 NIST CSF controls is assessed on a cadence — never point-in-time. The method sets a sensible default (live telemetry re-checks continuously, attestations on their review cycle); this sets a global floor you can tune per function or per control later in the cockpit. It is not a blunt "run everything weekly" knob — a policy attestation shouldn't run more than its review cycle.
