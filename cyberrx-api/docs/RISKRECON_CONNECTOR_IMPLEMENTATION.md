## API Integration Details

### Authentication

The connector uses the vault system to retrieve RiskRecon API credentials:

```bash
# Environment variable format
RISKRECON_APIKEY=your-api-key-here
```

### Request Format

```javascript
GET https://api.riskrecon.com/api/v1/companies/{domain}
Headers:
  Authorization: token={apiKey}
  Content-Type: application/json
  Accept: application/json
Timeout: 10 seconds
```

### Response Format

```json
{
  "grade": "B",
  "last_observed": "2026-05-30T12:00:00Z",
  "exposure_score": 55,
  "insecurity_rating": 40,
  "issue_velocity": 3,
  "findings": [
    {
      "severity": "critical",
      "name": "Exposed Database Port",
      "description": "PostgreSQL port 5432 exposed to internet"
    }
  ]
}
```

## Signal Schema

Each signal generated by the RiskRecon connector follows this structure:

```javascript
{
  signalName: 'RiskRecon Security Grade',
  severity: 'Low',  // Info, Low, Medium, High, Critical
  confidence: 100,   // 0-100
  observedAt: '2026-05-31T12:00:00.000Z',
  description: 'Overall security posture grade for example.com',
  recommendedAction: 'Continue improving security posture...',
  evidenceUrl: 'https://app.riskrecon.com/company/example.com',
  rawData: {
    grade: 'B',
    last_observed: '2026-05-30T12:00:00Z',
    vendor_domain: 'example.com',
    vendor_id: 'vendor-123'
  }
}
```

## Error Handling

### HTTP Status Codes

| Status | Error Message | Action |
|--------|---------------|--------|
| 200 | Success | Process response normally |
| 401 | Invalid API token | Return fallback signal with credential error |
| 403 | Forbidden - insufficient permissions | Return fallback signal with permission error |
| 404 | Company not found | Return fallback signal with not found error |
| 429 | Rate limit exceeded | Return fallback signal with rate limit error |
| 500+ | Server error | Return fallback signal with server error |

### Network Errors

- **Timeout (10s)**: Return fallback signal with timeout message
- **Network failure**: Return fallback signal with network error message
- **Invalid response**: Return fallback signal with validation error

### Fallback Signal

When the API is unavailable, the connector returns:

```javascript
{
  signalName: 'RiskRecon Data Unavailable',
  severity: 'Info',
  confidence: 0,
  description: 'Unable to retrieve RiskRecon data for {domain}...',
  recommendedAction: 'Verify RiskRecon API credentials and connectivity',
  rawData: {
    fallback: true,
    reason: 'API unavailable or credentials invalid'
  }
}
```

## Usage Example

### Basic Usage

```javascript
const RiskReconConnector = require('./src/connectors/RiskReconConnector');

const connector = new RiskReconConnector({
  organizationId: 'org-123',
  vendorId: 'vendor-456'
});

try {
  const signals = await connector.collectSignals(
    'example.com',  // vendor domain
    'vendor-456',    // vendor ID
    'org-123'        // organization ID
  );

  console.log(`Collected ${signals.length} signals from RiskRecon`);
  signals.forEach(signal => {
    console.log(`- ${signal.signalName}: ${signal.severity}`);
  });
} catch (error) {
  console.error('Failed to collect signals:', error.message);
}
```

### Connection Testing

```javascript
const result = await connector.testConnection();

if (result.status === 'success') {
  console.log('RiskRecon API connection successful');
} else {
  console.error('Connection failed:', result.message);
}
```

## Integration Points

### Dependencies

1. **BaseConnector** (`/src/connectors/BaseConnector.js`)
   - Extends base connector class
   - Uses `normalizeSignal()` for signal standardization
   - Inherits `storeSignals()` for database persistence

2. **Vault** (`/src/utils/vault.js`)
   - Retrieves RiskRecon API credentials
   - Environment variable: `RISKRECON_APIKEY`
   - AWS Secrets Manager support in production

3. **VendorRiskSignal** (`/src/models/VendorRiskSignal.js`)
   - Stores signals in database
   - Maintains signal history and metadata

### Data Flow

```
User Request
    ↓
collectSignals(vendorDomain, vendorId, organizationId)
    ↓
vault.get(organizationId, 'riskrecon') → API credentials
    ↓
fetch RiskRecon API → Company data
    ↓
validate response → Check for grade field
    ↓
mapRiskReconToSignals() → Normalize signals
    ↓
calculateSeverity() → Map grades to severity
    ↓
Return array of normalized signals
    ↓
storeSignals() → Persist to database (via BaseConnector)
```

## Troubleshooting

### Common Issues

#### Issue: "RiskRecon credentials not configured"

**Cause:** API key not set in environment or vault

**Solution:**
```bash
# Check environment variable
echo $RISKRECON_APIKEY

# Or check AWS Secrets Manager
aws secretsmanager get-secret-value \
  --secret-id cyberrx/{org-id}/riskrecon \
  --region us-east-1
```

#### Issue: "Invalid RiskRecon API token" (401)

**Cause:** API key is invalid or expired

**Solution:**
1. Verify API key in RiskRecon dashboard
2. Regenerate API key if needed
3. Update vault or environment variable
4. Restart application

#### Issue: "Company not found in RiskRecon database" (404)

**Cause:** Domain not tracked by RiskRecon

**Solution:**
1. Verify domain is correct
2. Add domain to RiskRecon monitoring
3. Check for typos in domain name

#### Issue: "Rate limit exceeded" (429)

**Cause:** Too many API requests

**Solution:**
1. Implement request throttling
2. Add exponential backoff
3. Contact RiskRecon for rate limit increase

#### Issue: "Connection timeout"

**Cause:** Network issues or RiskRecon service unavailable

**Solution:**
1. Check network connectivity
2. Verify RiskRecon service status
3. Increase timeout if needed (default: 10s)
