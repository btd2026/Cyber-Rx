# `workspace/context/` — agent context map

This directory holds context artifacts that downstream agents read instead of
loading large source files into their own context window. Every file here is
**regenerable** by a deterministic script and should be re-built on demand
rather than hand-edited.

## Files

| File | What it is | Regenerated by |
|---|---|---|
| `appjsx-index.json` | Structural index of `frontend/src/App.jsx` — every component with line range, anchor signature, local state, props read, cross-refs, and split-risk score. | `scripts/build_appjsx_index.py` |
| `assessment-full.md` | Single-file copy of the coverage assessment (input to the chunker). | manual / scripted copy of `COVERAGE_ASSESSMENT.md` |
| `assessment-chunks/` | Pre-split chunks of the assessment for narrow worker reads. | (chunker — out of scope of this README) |

## `appjsx-index.json` — schema v2.0

The index is the single source of truth for "what's in App.jsx and where."
It is the artifact that makes CLAUDE.md rule 1 (`NEVER open src/App.jsx in
full`) actually safe — workers consult it to find a narrow line range, then
read only that range.

### Top-level shape

```jsonc
{
  "schema_version": "2.0",
  "metadata": {
    "total_lines": 24559,
    "file_sha256": "...",
    "git_head":    "...",
    "generated_at":"2026-05-30T03:57:25Z",
    "extractor":   "scripts/build_appjsx_index.py",
    "rules": [...]
  },
  "navigation":       { "nav_line_range": [113,132], "pages": {...} },
  "shared_state_root":{ "component": "CyberRxApp", "useState_line_range": [23525,23849], ... },
  "export_default":   { "name": "CyberRxApp", "line": 24019, "note": "..." },
  "constants":        [ { "name":"NAV", "line_range":[113,132], ... }, ... ],
  "components":       [ { "name":"CISODash", "line_range":[7326,8407], ... }, ... ],
  "coverage":         { "covered_lines": 24556, "uncovered_ranges": [[1,3]], ... },
  "split_planning":   { "recommended_order":[...], "extract_first":[...], "do_not_extract_yet":[...] }
}
```

### Per-component fields a worker MUST trust

- **`line_range`** `[start, end]` — inclusive, 1-indexed.
- **`anchor_signature`** — first ~80 chars of the function definition line.
  A worker **must** verify the live file's line at `function_definition_line`
  still starts with this string before trusting `line_range`. If the anchor
  drifts, the index is stale; re-run `build_appjsx_index.py`.
- **`local_state`** — `useState` hook names actually present in the body.
- **`refs`** — `useRef` variable names.
- **`props_used`** — every `props.X` read in the body.
- **`cross_refs`** — every top-level constant or component name referenced
  from inside the body. This is the dependency graph an extraction needs to
  preserve.
- **`split_risk`** — `LOW` / `MEDIUM` / `HIGH` heuristic. **Heuristic, not a
  guarantee.** Re-evaluate before M6 PRs:
  - `HIGH` → mutates root state (`setRoot*`, `setExecActions`, `setPage`,
    `setPhase`) OR has 25+ cross-refs OR exceeds 1500 LOC.
  - `MEDIUM` → 10+ cross-refs OR 400+ LOC OR 3+ `useEffect`s.
  - `LOW` → none of the above.

### Worker usage (typical extraction PR)

```bash
# 1. Look up the page
jq '.components[] | select(.name=="CISODash") | .line_range' \
   workspace/context/appjsx-index.json
# → [7326, 8407]

# 2. Verify anchor before reading
sed -n '7326p' frontend/src/App.jsx | head -c 80
# → "function CISODash(props) {"

# 3. Now read the slice
sed -n '7326,8407p' frontend/src/App.jsx
```

### Regenerating the index

```bash
python3 scripts/build_appjsx_index.py
python3 scripts/validate_appjsx_index.py   # exits non-zero on drift
```

The validator must be green before any worker PR that depends on the index
is merged. Wire it into CI for M6.

## What changed from the seed index (schema 1 → 2.0)

- Added `schema_version`, `file_sha256`, `git_head`, accurate `generated_at`.
- Corrected `total_lines`: 24,539 → **24,559**.
- Filled the 17,333 → 18,519 "gap": that's `SetupBot`'s 1,186-line body, now
  bounded with a real `line_range`.
- Added 14 components the seed missed, including the **root component**
  (`CyberRxApp` @ 23,524–24,197), `BrianaBar`, the Attack-Path subcomponents
  (`Atk*`), the Crown-Jewels Discovery subcomponents (`Cjd*`), and the two
  CFO `Exposure*` components that live AFTER the `export default` (hoisting
  makes it work, but it's a footgun the M6 split must respect).
- Replaced placeholder `local_state: "[financial metrics state]"` strings
  with the actual `useState` names extracted from each body.
- Added `props_used` (every `props.X` read) and `cross_refs` (every top-level
  symbol referenced) per component — the data needed to schedule a clean
  extraction order.
- Added `split_risk` per component plus a `split_planning.recommended_order`
  that sorts LOW → HIGH → CyberRxApp.
- Added `coverage` accounting: 24,556 of 24,559 lines fall inside a known
  top-level definition. The 3 uncovered lines are the file header (`import
  React, ...` + blank + the first comment).
- Added a separate validator (`scripts/validate_appjsx_index.py`) that
  re-verifies the index against the live file via 8 checks and exits
  non-zero on any drift — suitable for CI gating.
